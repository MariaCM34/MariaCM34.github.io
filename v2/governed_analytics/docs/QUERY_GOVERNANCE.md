# Query governance and threat model

The exposed input is a Pydantic object with a four-value metric enum, two bounded dates, a two-value currency enum, and an optional three-value category enum. Extra fields are forbidden. The user cannot submit SQL, table names, expressions, joins, file paths, URLs, or UDFs. `compile_query` selects a reviewed SQL template and binds filter values; the API opens the DuckDB warehouse with `read_only=True`, caps grouped output at 500 rows, and interrupts a query after 2 seconds. The local server should bind `127.0.0.1` only.

For unsupported intent, malformed dates/currency, attempts to supply `sql`, or injection text, `/api/query` responds 422 with a query ID and no rows or prior SQL. The browser hides the previous result before every request and leaves it hidden after refusal. An audit row in a separate SQLite database stores ID, UTC timestamp, status (`EXECUTED`, `REFUSED`, `ERROR`), generic reason, and typed request summary. Refusal payloads are not stored verbatim, avoiding accidental retention of malicious or personal text. Audit access is local and not authenticated, so the service must not be exposed publicly.

Threats addressed: query injection, arbitrary table access, DDL/DML, multi-statement writes, stale UI results, cross-currency aggregation, oversize date range, and accidental writes to the analytical snapshot. Threats **not** addressed for public deployment: authentication, authorization, rate limiting, multi-tenant isolation, audit retention, network DoS, secret management, and customer data governance. This is a local synthetic reference. Public Pages may host only the generated, labeled static evidence JSON after a release review.

Why rule-based rather than model-guided text-to-SQL: the four required metrics have stable semantics, so deterministic selection is easier to audit, test and bound. A future LLM could propose a semantic action but would need prompt-injection tests, policy validation, cost limits, and observed quality evidence. Unconstrained text-to-SQL is rejected because a read-only DB still permits costly scans and unapproved data access. No AI call exists in this package.
